# Documentação do domínio

Este repositório usa um único contexto para backend e frontend. Antes de alterar regras do domínio, leia `CONTEXT.md` na raiz e os ADRs pertinentes em `docs/adr/`, se existirem. Use os termos definidos ali em nomes de testes, interfaces e documentação.

Crie `CONTEXT.md` apenas quando um termo do domínio for definido. Crie um ADR apenas para uma decisão difícil de reverter, surpreendente sem contexto e resultado de uma escolha real. A skill `domain-modeling` orienta esses registros.
